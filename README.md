# Домашнее задание к занятию «Уязвимости и атаки на информационные системы» - Нефедов Александр


Задание 1
<details>
Проведите разведку системы и определите, какие сетевые службы запущены на защищаемой системе:

sudo nmap -sA < ip-адрес >

sudo nmap -sT < ip-адрес >

sudo nmap -sS < ip-адрес >

sudo nmap -sV < ip-адрес >

По желанию можете поэкспериментировать с опциями: https://nmap.org/man/ru/man-briefoptions.html.

В качестве ответа пришлите события, которые попали в логи Suricata и Fail2Ban, прокомментируйте результат.

---
</details>

На Debian 192.168.56.102 выполнено сканирование Nmap в режимах ACK (-sA), TCP Connect (-sT), SYN (-sS) и определения версий (-sV).


Среди 1000 проверенных TCP-портов обнаружена служба SSH на порту 22 — OpenSSH 10.0p2 Debian 7+deb13u4. Порт 53 имеет состояние filtered: ответа нет, поэтому наличие службы DNS не подтверждено. Остальные 998 портов закрыты.

А Suricata зарегистрировала события по созданным правилам:

11/14/2026-16:38:42.420399
LAB Frequent ACK packets
192.168.56.1:56443 -> 192.168.56.102:25

11/14/2026-16:39:01.955634
LAB Frequent SYN packets
192.168.56.1:44030 -> 192.168.56.102:3784

Эти события показывают частые ACK- и SYN-пакеты от сканирующей машины 192.168.56.1. Порты в сообщениях — адресаты пакетов, их указание не означает, что они открыты.

Fail2Ban во время сканирования не зарегистрировал ошибок входа и блокировок:

Total failed:     0
Currently banned: 0
Total banned:     0

Suricata обнаружила сетевую активность, а Fail2Ban не сработал, поскольку настроенная защита SSH отслеживает ошибки аутентификации, которых при сканировании не было.

Задание 2
<details>
Проведите атаку на подбор пароля для службы SSH:

hydra -L users.txt -P pass.txt < ip-адрес > ssh

Настройка hydra:
создайте два файла: users.txt и pass.txt;
в каждой строчке первого файла должны быть имена пользователей, второго — пароли. В нашем случае это могут быть случайные строки, но ради эксперимента можете добавить имя и пароль существующего пользователя.
Дополнительная информация по hydra: https://kali.tools/?p=1847.

Включение защиты SSH для Fail2Ban:
открыть файл /etc/fail2ban/jail.conf,
найти секцию ssh,
установить enabled в true.
Дополнительная информация по Fail2Ban:https://putty.org.ru/articles/fail2ban-ssh.html.

В качестве ответа пришлите события, которые попали в логи Suricata и Fail2Ban, прокомментируйте результат.

---
</details>

Защита SSH включена в /etc/fail2ban/jail.d/sshd.local, секция [sshd]; maxretry = 5, findtime = 5m, bantime = 5m


Выполнен подбор паролей SSH с помощью Hydra с машины 192.168.56.1 на Debian 192.168.56.102.


Suricata обнаружила повторные подключения к порту 22:

11/14/2026-16:44:48.760529 [1:1000003:1]
LAB Repeated SSH connection attempts
192.168.56.1:35504 -> 192.168.56.102:22


В журнале SSH появились ошибки входа с несуществующими пользователями:

Failed password for invalid user lab_invalid_user1 from 192.168.56.1


Fail2Ban обнаружил ошибки и зарегистрировал блокировку адреса:

2026-11-14 16:44:52,267 fail2ban.actions [2150]:
NOTICE [sshd] Ban 192.168.56.1


Статус Fail2Ban подтвердил наличие адреса в списке заблокированных:

Total failed:     13
Currently banned: 1
Total banned:     1
Banned IP list:   192.168.56.1


Suricata зафиксировала подозрительную сетевую активность, а Fail2Ban обработал ошибки входа из журнала SSH и применил блокировку на пять минут. Счётчик Total failed: 13 обозначает в целом обнаруженные события.
